# Registro de decisiones arquitectónicas

Toda decisión que cambie límites, tecnologías, contratos globales o invariantes requiere un ADR.

Estados permitidos: `proposed`, `accepted`, `rejected`, `superseded`. Solo un ADR `accepted` tiene autoridad arquitectónica. La aceptación requiere aprobación explícita del Product Owner y fecha registrada.

Cada ADR debe contener contexto, decisión o alternativas, consecuencias, evidencia, estado y relación con otros ADR. Los nombres usan `NNNN-slug.md`; un ADR aceptado no se reescribe para ocultar historia, sino que se reemplaza mediante otro ADR.
